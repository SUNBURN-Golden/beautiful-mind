# Beautiful Mind MVP - Definition of Done (DoD)

각 Core 모듈별 MVP 완료 조건 (체크리스트)입니다. 해당 조건이 모두 충족되어야 기능 출시가 가능합니다.

## 1. Auth & Consent (인증 및 동의)
- [ ] 회원가입/로그인 파이프라인이 정상 동작하는가?
- [ ] 회원가입 단계에서 `docs/legal`의 법적 텍스트를 무결하게(외부 및 자체 수정/가공 없이 File-read로) 불러와 화면에 렌더링하는가?
- [ ] 민감 정보(OSINT, 위치, 기기) 처리 전 명시적 동의(Opt-in) 체크박스 및 설명이 명확히 제시되는가?
- [ ] 설정(Settings) 메뉴에서 사용자가 터치 3회 이내로 '동의 철회(Opt-out)'를 즉각적으로 실행할 수 있는가?
- [ ] 동의 철회 시 DB 및 세션에 있는 해당 모듈의 권한 토큰이 즉시 폐기되어 백엔드 호출이 거절되는가?

## 2. OSINT 모듈 (검증)
- [ ] OSINT 정보 수집 API 호출 전 사용자 Consent Table의 `is_granted` 값이 True인지 사전에 검증하는가?
- [ ] 평가된 신뢰도/데이터가 타 모듈과 분리된 형태(마이크로서비스 또는 격리된 API 라우트)로 전송 및 저장되는가?
- [ ] OSINT 데이터가 DB에 기록될 때 RLS 정책이 정상적으로 작동하여 본인 외 다른 유저의 접근을 완벽히 차단하는가?

## 3. Location & Device 모듈 (위치 및 기기 무결성)
- [ ] 위치 인증(GPS & Network IP) 요청 전, 1회성 또는 세션 한정 권한 동의를 명확히 사용자에게 묻는가?
- [ ] 디바이스 무결성(Jailbreak/Rooting 탐지, Emulator 탐지 등) 체크 로직이 정상 동작하는가?
- [ ] 위치 정보 스푸핑 시도 감지 로직(예: 비정상적 순간 이동 속도, IP 대역과 GPS 좌표 불일치)이 포함되었는가?

## 4. Threat Mitigation & Penalty 모듈 (위협 방어 및 패널티)
- [ ] 다수의 사용자가 특정 대상을 허위로 일제히 신고(Sybil/Collusion Attack)할 경우, 룰 기반(규칙/가중치)으로 이를 탐지해 즉각 처벌 대신 "보류(Pending)" 상태로 전환하는가?
- [ ] 허위 신고자(악성 리포터) 패턴 적발 시 프로세스(1차 경고 -> 2차 소명 기회 제공 -> 서비스 제한)에 따라 '역패널티'가 단계별로 부과되는가?
- [ ] **필수:** 어떠한 경우에도 시스템에 의한 "자동 영구 정지(Auto-Ban)"가 즉시 발생하지 않도록 코어 로직에 예방책(Assert/Guard)이 있는가?

## 5. Architecture & Security (아키텍처 및 보안 공통)
- [ ] 각 코어 모듈(Auth, OSINT, Location, Device, Penalty)의 기능이 물리적 또는 논리적(Router 레벨)으로 완전히 분리되어 한 모듈의 장애/버그가 타 모듈을 중단시키지 않는가?
- [ ] 모든 API 엔드포인트에 인증 요청 횟수 제한(Rate Limiting)이 적용되어 있는가?
- [ ] DB의 모든 테이블에 Row Level Security (RLS) 정책이 활성화되어 있고 자동화(또는 수동) 보안 테스트(비인가 Admin 우회 불가 등)를 통과했는가?
